A **policy** is a small object with one method:

```ts
interface Policy {
  execute<T>(op: (ctx: PolicyContext) => Promise<T>, parent?: PolicyContext): Promise<T>
}

interface PolicyContext {
  signal: AbortSignal // abort cooperatively on timeout
  attempt: number     // 0-based retry attempt
}
```

Every built-in policy is a factory that returns one. They share the same shape, so they compose. The optional `parent` argument is how `wrap` threads context (and the abort signal) from an outer layer into an inner one — you rarely pass it by hand. `rootContext()` produces the never-aborting context used at the top of a chain.

## `wrap` — compose policies

`wrap(...policies)` builds one policy from many. The **first argument is the outermost** layer; the last sits closest to your operation:

```ts
import { wrap, timeout, retry, circuitBreaker } from '@adonis-agora/resilience'

const policy = wrap(timeout(2_000), retry({ attempts: 3 }), circuitBreaker({ /* … */ }))
// execution order: timeout( retry( circuitBreaker( op ) ) )
```

Read it top-down: the timeout bounds the *entire* retry loop; the breaker wraps each individual attempt. Order matters — put `timeout` inside the `retry` instead if you want a per-attempt deadline (see the recipe below).

## `timeout`

```ts
timeout(ms: number, opts?: { clock?: Clock; onEvent?: EventSink }): Policy
```

Rejects with a **`TimeoutError`** if the operation hasn't settled within `ms`, and aborts the `PolicyContext.signal` so cooperating work can stop:

```ts
import { timeout, TimeoutError } from '@adonis-agora/resilience'

try {
  await timeout(5_000).execute(({ signal }) => fetch(url, { signal }))
} catch (err) {
  if (err instanceof TimeoutError) console.warn(`timed out after ${err.ms}ms`)
}
```

<Callout type="warn">
A timeout can only *cancel* work that listens to the `AbortSignal`. Always thread `ctx.signal` into your HTTP client / DB driver — otherwise the timeout rejects the promise but the underlying request keeps running.
</Callout>

The `timeout` policy also forwards aborts from its `parent` context, so an outer timeout cancels an inner one.

Pass `onEvent` to observe the deadline being hit — the sink receives a `timeout` event carrying `ms`. Like every policy, a `timeout` you build yourself is silent unless you wire it: see [which policies get the service's sink](/docs/resilience/integrations#which-policies-get-the-services-sink).

## `retry` and backoff

```ts
retry(opts: { attempts: number; backoff?: Backoff; clock?: Clock; onEvent?: EventSink }): Policy
```

Re-runs the operation up to `attempts` times, waiting `backoff(attempt)` milliseconds between tries. After the last failure it rethrows the final error. `attempts: 3` means **three total tries**. The backoff defaults to `() => 0` (no wait), and each attempt sees its 0-based index on `ctx.attempt`. The inter-attempt delay honours the parent's `AbortSignal`, so a wrapping timeout cuts a pending backoff short.

`Backoff` is just `(attempt: number) => number`. The package ships `exponential`:

```ts
exponential(baseMs: number, opts?: { jitter?: boolean; factor?: number; maxMs?: number }): Backoff
```

```ts
import { retry, exponential } from '@adonis-agora/resilience'

retry({ attempts: 4, backoff: exponential(100) })
// waits 100ms, 200ms, 400ms between the four attempts (factor defaults to 2)

retry({ attempts: 4, backoff: exponential(100, { jitter: true, factor: 3 }) })
// 100ms·3^n, each randomized to 50–100% to spread out a thundering herd

retry({ attempts: 10, backoff: exponential(500, { maxMs: 30_000 }) })
// 500ms, 1s, 2s, 4s, 8s, 16s, then capped at 30s for every remaining attempt
```

`maxMs` caps the computed delay *before* jitter is applied, so a jittered delay never exceeds the cap either. It is optional and **off by default** — `exponential()` does not impose an implicit ceiling (e.g. 30s) on your behalf, even though that would be the "safer" default for most callers. Two reasons: it's a standalone exported helper used outside `retry()` too, and quietly changing an already-deployed delay curve on a routine upgrade is worse than leaving it uncapped. In practice, once `attempts` climbs past a handful, always pass `maxMs` — an uncapped exponential curve reaches minutes-long waits within 8–10 attempts at the default `factor: 2`:

```ts
retry({ attempts: 12, backoff: exponential(200, { maxMs: 30_000, jitter: true }) })
```

Pass `onEvent` to observe the re-attempts: the sink receives a `retry` event before each one, carrying `attempt` (the 1-based number of the *upcoming* try) and `error` (the failure that triggered it).

There's no `constant()` helper — a fixed delay is just a function:

```ts
retry({ attempts: 5, backoff: () => 250 }) // always 250ms
```

## `circuitBreaker`

```ts
circuitBreaker(opts: {
  key: string
  store?: ResilienceStore | string  // a store, or a store name from config (named policies)
  threshold: number       // consecutive failures before opening
  cooldownMs: number      // how long to stay open before probing
  halfOpenMax?: number    // concurrent probes allowed in half-open (default 1)
  onEvent?: EventSink
}): Policy
```

Tracks failures per `key` in a [store](/docs/resilience/stores). After `threshold` failures it **opens** — every call fails fast with a **`BrokenCircuitError`** instead of hammering a dead dependency. After `cooldownMs` it goes **half-open** and lets a single probe through; a success **closes** it, a failure re-opens it.

```ts
import { circuitBreaker, BrokenCircuitError, InMemoryResilienceStore } from '@adonis-agora/resilience'

const breaker = circuitBreaker({
  key: 'inventory-api',
  store: new InMemoryResilienceStore(),
  threshold: 5,
  cooldownMs: 30_000,
})

try {
  await breaker.execute(() => inventory.check(sku))
} catch (err) {
  if (err instanceof BrokenCircuitError) {
    // err.key === 'inventory-api' — short-circuited, don't even try
  }
}
```

Pass the same store instance to every breaker that should share state. In a policy registered under `policies` in [`config/resilience.ts`](/docs/resilience/adonis), name a store from `stores` (`store: 'redis'`) or leave `store` out to use the default one. A breaker built anywhere else without a `store` uses one in-memory store shared by the whole process.

<Callout type="info">
The in-memory store keeps breaker state per process. To trip the breaker fleet-wide — one instance opens, all instances skip — pass a distributed store and the half-open probe is coordinated atomically. See [Stores](/docs/resilience/stores).
</Callout>

## `bulkhead`

```ts
bulkhead(opts: {
  key: string
  limit: number            // calls allowed to run at once
  queue?: number           // calls allowed to wait for a slot, per process (default 0: reject)
  queueTimeoutMs?: number  // how long a queued call waits (default 10s)
  leaseMs?: number         // a slot is freed after this long if its process died (default 60s)
  pollMs?: number          // how often a queued call re-checks a shared store (default 50ms)
  store?: BulkheadStore | string
  onEvent?: EventSink
}): Policy
```

Caps how many calls run at once, so one slow dependency cannot take every worker or connection with it. Past `limit`, a call waits in the queue (up to `queue` callers, for up to `queueTimeoutMs`) or fails at once with **`BulkheadRejectedError`** (`reason`: `'full'`, `'queue-full'` or `'queue-timeout'`).

```ts title="config/resilience.ts"
import { defineConfig, stores, wrap, bulkhead, timeout } from '@adonis-agora/resilience'

export default defineConfig({
  default: 'redis',
  stores: { redis: stores.redis({ connection: 'main' }) },
  policies: {
    // at most 10 report renders at once across the fleet, 20 more may wait up to 5s
    reports: () => wrap(bulkhead({ key: 'reports', limit: 10, queue: 20, queueTimeoutMs: 5_000 }), timeout(30_000)),
  },
})
```

With the memory store the limit is per process and a queued call starts the moment a slot is released. With Redis or Lucid the limit holds across every process; queued calls re-check every `pollMs`. Set `leaseMs` above your slowest call: a call running longer than that stops counting against the limit.

Turn the rejection into a `503` in the controller:

```ts title="app/controllers/reports_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'
import resilience from '@adonis-agora/resilience/services/main'
import { BulkheadRejectedError } from '@adonis-agora/resilience'
import ReportService from '#services/report_service'

export default class ReportsController {
  async show({ params, response }: HttpContext) {
    try {
      return await resilience.execute('reports', () => ReportService.render(params.id))
    } catch (error) {
      if (error instanceof BulkheadRejectedError) {
        return response.serviceUnavailable({ message: 'Too many reports are being generated, try again shortly' })
      }
      throw error
    }
  }
}
```

## `rateLimiter`

```ts
rateLimiter(opts: {
  key: string
  limit: number        // calls allowed per interval
  intervalMs: number
  burst?: number       // calls allowed at once after a quiet period (default `limit`)
  cost?: number        // tokens one call takes (default 1)
  maxWaitMs?: number   // wait this long for budget instead of failing (default 0)
  store?: RateLimitStore | string
  onEvent?: EventSink
}): Policy
```

Keeps outbound calls under a provider's quota (a token bucket: `limit` tokens refill evenly over each `intervalMs`). Over budget, a call waits up to `maxWaitMs` for the next token or fails with **`RateLimitedError`**, which carries `retryAfterMs`.

```ts title="config/resilience.ts"
policies: {
  // the SMS provider allows 100 requests per minute for the whole account
  sms: () => wrap(rateLimiter({ key: 'sms', limit: 100, intervalMs: 60_000, maxWaitMs: 2_000 }), retry({ attempts: 2 })),
}
```

```ts title="app/jobs/send_sms_job.ts"
import resilience from '@adonis-agora/resilience/services/main'
import { RateLimitedError } from '@adonis-agora/resilience'

export default class SendSmsJob {
  async handle(payload: { to: string; body: string }) {
    try {
      await resilience.execute('sms', () => sms.send(payload))
    } catch (error) {
      if (error instanceof RateLimitedError) return this.release(error.retryAfterMs)
      throw error
    }
  }
}
```

With the memory store each process has its own budget; with Redis or Lucid one budget is shared by the fleet, which is what a provider quota needs.

## `failover`

`failover()` walks an ordered list of targets, running each through an optional per-target policy, and returns the first success. When **every** target fails it throws the last error (and throws immediately if `targets` is empty).

```ts
failover<TTarget, R>(opts: {
  targets: TTarget[]
  run: (target: TTarget, ctx: PolicyContext) => Promise<R>
  policy?: (target: TTarget) => Policy
  onFailover?: (target: TTarget, error: unknown, index: number) => void
  onEvent?: EventSink
}): Promise<R>
```

Unlike the other policies, `failover` runs immediately and returns the result — it's a function, not a `Policy`. Give each target its own breaker + timeout so a known-dead target is skipped instantly:

```ts
import { failover, wrap, timeout, circuitBreaker, InMemoryResilienceStore } from '@adonis-agora/resilience'

const store = new InMemoryResilienceStore()

const sms = await failover({
  targets: [twilio, vonage, sns],
  run: (provider, { signal }) => provider.send(message, { signal }),
  policy: (provider) =>
    wrap(circuitBreaker({ key: `sms:${provider.id}`, store, threshold: 5, cooldownMs: 30_000 }), timeout(8_000)),
  onFailover: (provider, err, i) => logger.warn(`sms #${i} ${provider.id} failed: ${err}`),
})
```

Each failover step emits a `failover` event carrying `target` (stringified), `index`, and `error` — but only to a sink you pass as `onEvent`. Calling the exported `failover()` directly, as above, emits **nowhere**: it takes no ambient sink, so nothing reaches diagnostics or your EventEmitter mirror. Call it through [`ResilienceService.failover`](/docs/resilience/adonis#the-service) to get the service's sink wired in for you, or pass `onEvent` yourself. `onFailover` fires either way.

## Recipe: per-attempt timeout

Putting `timeout` **inside** `retry` bounds each try rather than the whole loop, so a single slow attempt is retried instead of failing the lot:

```ts
const policy = wrap(retry({ attempts: 3, backoff: exponential(100) }), timeout(1_000))
await policy.execute(() => callOnce())
// retry( timeout( callOnce ) ) — each attempt has its own 1s deadline
```

## Errors

| Error | Thrown by | Carries |
| --- | --- | --- |
| `TimeoutError` | `timeout` | `ms` — the deadline that elapsed |
| `BrokenCircuitError` | `circuitBreaker` | `key` — the open circuit's key |
| `BulkheadRejectedError` | `bulkhead` | `key`, `reason` (`'full'`, `'queue-full'`, `'queue-timeout'`) |
| `RateLimitedError` | `rateLimiter` | `key`, `retryAfterMs` |

All extend `Error` with a stable `name`, so `instanceof` checks work across module boundaries.
